LLM inference splits into two phases with distinct bottlenecks. **Prefill** processes the full prompt in parallel via large matrix multiplications, making it compute-bound; its latency determines time to first token. **Decode** generates one token at a time, reusing a KV cache of previously computed key-value projections to avoid recomputation. Because each decode step reads all model weights and cached activations but performs minimal arithmetic, it is memory-bandwidth-bound rather than compute-bound — explaining why decode throughput depends on memory speed more than raw FLOPS.

Speculative decoding accelerates decode by decoupling token guessing from verification. A draft mechanism proposes multiple candidate tokens, and the target model verifies them all in a single forward pass, incurring the same memory traffic as one token while potentially accepting several. Output quality remains mathematically identical to the full model. Multi-Token Prediction (MTP) is a variant that attaches extra prediction heads to the base model itself, eliminating the need for a separate draft model's weights in memory.

The real determinant of speedup is the **acceptance rate** — the fraction of drafted tokens the verifier accepts. This varies by workload: structured code tends to yield higher acceptance than free-form prose, since token sequences are more predictable. Hardware also matters: GPUs with high compute-to-bandwidth ratios see dramatic speedups, while Apple Silicon's unified memory architecture and different balance produce different results for the same acceptance rate. Ultimately, MTP and speculative decoding only pay off when acceptance rates are measured empirically on the target hardware, quantization, and workload — never assumed from benchmarks on a different setup.
