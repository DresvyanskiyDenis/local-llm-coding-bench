The document explains how LLM inference on local hardware is split into two distinct stages. Prefill processes the whole prompt in a single forward pass, making heavy use of parallel matrix multiplication, so its latency is limited by the GPU’s compute power (floating‑point operations). Decode, by contrast, generates output tokens one at a time; each step must read the full set of model weights and the cached key‑value pairs for all previous tokens, but performs little arithmetic. Thus decode is bottlenecked by memory bandwidth rather than compute, explaining why throughput hardly changes with faster cores but does with higher bandwidth.

To avoid recomputing attention at every decode step, engines keep a KV cache that stores the key and value projections for every token seen so far. The cache grows linearly with context length, the number of layers, and heads, so memory limits often reduce usable context more than the model’s theoretical maximum. Quantizing the cache to lower precision can reclaim space.

Speculative decoding tackles the memory‑bandwidth cost of decode by separating “drafting” from “verifying.” A cheap draft model (or, in the Multi‑Token Prediction variant, additional prediction heads attached to the base model) proposes several candidate tokens in parallel. The base model then verifies all candidates in one forward pass. If a draft token is accepted, several output tokens are produced per pass; otherwise the base model’s own prediction takes over. The method does not degrade quality but can substantially raise throughput when the draft acceptance rate is high.

The acceptance rate, i.e., the fraction of drafted tokens that pass verification, is the key metric. Structured, repetitive tasks such as code generation typically yield higher rates than free‑form prose. Speculative decoding’s benefit also depends on hardware: GPUs with high compute‑to‑bandwidth ratios (e.g., NVIDIA CUDA cards) realize larger speedups, while Apple Silicon’s unified memory and different bandwidth balance can limit gains.

The take‑aways for local model deployment are that prefill time is dominated by compute, so faster cores help for quick responses; decode speed depends mainly on memory bandwidth, so choosing a GPU or platform with higher bandwidth improves long‑generation throughput. Models equipped with MTP heads can accelerate decode without the overhead of a separate draft model, but only when the measured acceptance rate on the target hardware and workload is sufficiently high.
