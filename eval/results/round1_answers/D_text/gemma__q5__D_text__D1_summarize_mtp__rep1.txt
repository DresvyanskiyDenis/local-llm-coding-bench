LLM inference consists of two distinct phases: prefill and decode. The prefill phase, which handles the initial prompt, is compute-bound because it performs parallel matrix multiplications. In contrast, the decode phase—generating tokens one by one—is memory-bandwidth-bound. This is because each step requires loading all model weights and the KV cache from memory while performing minimal arithmetic, making memory speed the primary bottleneck for throughput.

To manage the growing memory requirements of the KV cache, engines store previous key and value projections, though this can lead to memory budget constraints on hardware with limited RAM. Speculative decoding addresses the inefficiency of the decode phase by using a "draft" mechanism to propose multiple candidate tokens. A larger target model then verifies these candidates in a single forward pass, which consumes roughly the same memory bandwidth as a single-token decode. This approach can significantly increase throughput without sacrificing output quality. Variants like Multi-Token Prediction (MTP) achieve similar results by adding extra prediction heads directly to the base model, avoiding the memory overhead of a separate draft model.

The effectiveness of these methods depends on the "acceptance rate"—how many drafted tokens the verifier actually accepts. This rate varies by workload, with highly structured tasks like code generation typically yielding higher rates than prose. Ultimately, the performance gains from speculative decoding are highly dependent on the specific hardware's compute-to-bandwidth ratio.
