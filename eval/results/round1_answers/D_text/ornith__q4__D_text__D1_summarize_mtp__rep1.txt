The document explains that LLM inference has two phases: **prefill**, which processes the full prompt in parallel and is compute-bound (limiting time-to-first-token), and **decode**, which generates one token at a time and is memory-bandwidth-bound because each step must stream all model weights and KV cache through memory while doing little arithmetic. The KV cache, storing key/value projections per layer, grows with context length and competes with model weights for memory — especially problematic on unified-memory systems like Apple Silicon where RAM is shared with the OS.

Speculative decoding addresses decode's inefficiency by decoupling token proposal from verification: a draft mechanism proposes multiple candidate tokens at once, then the target model verifies them all in a single forward pass. If accepted, several tokens are produced per pass; if rejected, the model falls back to its own prediction, preserving output quality exactly. Multi-Token Prediction (MTP) is a variant that avoids a separate draft model by attaching small extra prediction heads to the base model, trained to predict several future tokens — eliminating the memory cost of loading a second set of weights.

The key metric is **acceptance rate** — the fraction of drafted tokens the verifier accepts. Higher acceptance yields greater speedup, and this rate varies by workload: structured code tends to accept more than free-form prose. Finally, hardware matters: GPUs with high compute-to-bandwidth ratios see dramatic speedups from speculative decoding, while Apple Silicon's unified memory architecture and different balance require empirical measurement rather than assuming results from other platforms.
