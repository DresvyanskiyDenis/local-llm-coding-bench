This technical document explains how LLM inference hardware bottlenecks differ between two distinct phases. Prefill processes the entire prompt in parallel, making it compute-bound where speed depends on GPU FLOPS. Decode generates tokens one at a time, becoming memory-bandwidth-bound as the GPU's compute units idle waiting for weights and cached activations. To avoid recomputing attention, inference engines maintain a KV cache storing key/value projections for all generated tokens, which grows with context length and model complexity, creating memory budget constraints. 

Speculative decoding addresses decode inefficiency by separating guessing from verifying. A draft mechanism proposes multiple candidate tokens simultaneously, then the target model verifies all candidates in a single forward pass. Multi-Token Prediction (MTP) achieves this without a separate model by attaching extra prediction heads to the base model, trained to predict several future tokens from the same hidden state. 

Acceptance rate determines actual speedup: high rates mean most drafts are correct, multiplying effective throughput; low rates make draft generation overhead. Code generation achieves higher acceptance than prose due to structured patterns. Hardware balance matters critically—speedup depends on compute-to-bandwidth ratio, not just FLOPS, with Apple Silicon's unified memory affecting results differently than data-center GPUs.
