The document explains that LLM inference consists of two distinct phases with different performance bottlenecks. Prefill processes the entire input prompt in parallel, making it compute-bound and determining the "time to first token." Decode generates output one token at a time, becoming memory-bandwidth-bound as it constantly streams weights and cached activations between memory and compute units. To avoid recomputing attention from scratch at each decode step, inference engines maintain a KV cache storing key-value projections for all previous tokens.

Speculative decoding addresses decode inefficiency by separating token prediction from verification. A lightweight draft model (or Multi-Token Prediction heads attached to the base model) proposes multiple candidate tokens at once, which are then verified in a single forward pass of the main model. This allows several output tokens to be accepted per verification when drafts are accurate, dramatically improving throughput without sacrificing output quality.

The effectiveness hinges on acceptance rate—the fraction of drafted tokens accepted. Higher acceptance yields greater speedups, with structured workloads like code generation typically achieving better rates than free-form prose. Hardware characteristics also matter, as the speedup depends on the balance between compute throughput and memory bandwidth, meaning results vary across different GPUs (CUDA vs. Apple Silicon).

Practically, this means prefill time dominates short interactions, while decode speed determines long-generation performance, and MTP offers a memory-efficient way to accelerate decode without requiring a separate draft model.
