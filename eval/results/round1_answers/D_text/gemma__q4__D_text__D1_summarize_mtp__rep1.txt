LLM inference consists of two distinct phases: prefill and decode. The prefill phase, which processes the initial prompt, is compute-bound because it performs large-scale parallel matrix multiplications. In contrast, the decode phase, which generates tokens sequentially, is memory-bandwidth-bound. During decoding, the GPU spends most of its time moving massive amounts of model weights and KV cache data through memory rather than performing arithmetic, making memory bandwidth the primary bottleneck for generation speed.

To mitigate the inefficiency of the decode phase, speculative decoding uses a "draft" mechanism to propose multiple candidate tokens that the main model then verifies in a single forward pass. This approach can significantly increase throughput without sacrificing output quality. A variation called Multi-Token Prediction (MTP) achieves this by adding extra prediction heads directly to the base model, avoiding the memory overhead of a separate draft model.

The effectiveness of these techniques depends heavily on the "acceptance rate"—the frequency with which the verifier accepts the drafted tokens. This rate varies by task; for instance, structured code generation often yields higher acceptance rates than free-form prose. Ultimately, the performance gains from speculative decoding are tied to the specific hardware's compute-to-bandwidth ratio, meaning speedups must be measured directly on the target system rather than assumed from theoretical benchmarks.
