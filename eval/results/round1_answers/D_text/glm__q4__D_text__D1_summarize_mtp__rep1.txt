LLM inference operates through two distinct phases with different performance characteristics. Prefill processes the entire input prompt in a single forward pass, making it compute-bound and determining the "time to first token" user experience. Decode generates output one token at a time, moving large amounts of cached key/value projections through memory but performing minimal arithmetic, which makes it memory-bandwidth-bound rather than compute-bound. The KV cache stores these projections to avoid recomputing attention over the entire prefix at each decode step, but its memory requirements grow linearly with context length and model complexity, creating a real constraint on usable context length even when the model's theoretical maximum is higher.

Decode's inefficiency stems from requiring full passes over all weights for each token. Speculative decoding addresses this by separating token guessing from verification: a cheap mechanism proposes multiple candidate tokens, then the expensive target model verifies them in a single forward pass. Multi-Token Prediction (MTP) achieves similar results by attaching small prediction heads directly to the base model, trained to forecast several future tokens rather than just the immediate next one. The method's effectiveness depends entirely on acceptance rate—the fraction of drafted tokens that get accepted—which varies significantly by workload: code generation typically sees higher rates than free-form prose. Hardware balance between compute throughput and memory bandwidth critically determines the payoff, as different GPUs and unified-memory systems like Apple Silicon yield different speedup ratios for the same acceptance rate.
