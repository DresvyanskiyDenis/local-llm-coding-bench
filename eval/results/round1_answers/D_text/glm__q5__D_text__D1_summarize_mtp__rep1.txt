LLM inference consists of two phases with very different bottlenecks. Prefill processes the entire input prompt in parallel, making it compute-bound — its speed depends on GPU floating-point throughput. Decode generates output one token at a time, moving lots of data through memory but performing little arithmetic, so it's memory-bandwidth-bound. To avoid recomputing attention over the whole prefix each step, inference engines maintain a KV cache storing key/value projections per token.

Speculative decoding attacks decode's inefficiency by separating guessing from verification. A draft mechanism proposes multiple candidate tokens at once, and the target model verifies them in a single forward pass. If most guesses are correct, several tokens get accepted per pass, multiplying throughput. Multi-Token Prediction (MTP) is a variant that avoids a separate draft model by attaching extra prediction heads directly to the base model.

The metric that determines speedup is the acceptance rate — the fraction of drafted tokens the verifier accepts. High acceptance rates mean one verification pass produces several output tokens "for free." Acceptance rate varies by workload: code generation sees higher rates than free-form prose. Hardware matters because speculative decoding's payoff depends on the compute-to-bandwidth balance. On high-compute GPUs, verification is nearly free; on Apple Silicon with unified memory, the same acceptance rate doesn't guarantee the same speedup. Practically, prefill benefits from faster compute cores, decode from higher memory bandwidth, and MTP can speed up decode without extra memory costs — but only if the measured acceptance rate on your specific hardware and workload justifies it.
